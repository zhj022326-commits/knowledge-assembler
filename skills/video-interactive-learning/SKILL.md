# 信息流学习机

## 任务

把一个视频链接直接变成学习材料：取得尽可能完整的原始文字稿，只做一次可用性判断，适度整理知识，然后沿用互动学习模块立即开学。

默认顺序必须是：

`平台字幕 → 音频语音识别 → 一次抽帧取字救稿 → 质量判断 → 知识整理 → 互动学习`

核心目标是拿到稿子。抽帧只是语音路线失败后的救稿手段，不是让用户看画面，也不是常规视频理解。

## 启动规则

1. 从用户输入中识别抖音、B站、YouTube 或阅影/yt-dlp 支持的平台链接。分享文案中同时含标题和链接时，以链接为输入，并保留标题作为线索。
2. 用户只给视频链接且没有提出其他任务时，按学习请求启动；不要先追问学习模式、基础水平或课程长度。
3. 用户明确只要逐字稿时，在得到可用稿件后交付逐字稿，不自动进入教学。
4. 用户明确只要摘要、翻译、改写或数据时，完成指定任务，不强制转成互动学习。
5. 遇到私密、登录、地区限制或已下架内容，只说明具体阻断点；不得伪造文字稿。

## 一、准备运行环境

优先使用宿主已经具备、且能返回完整文字稿的读取能力。只有它会强制做整段画面分析、只返回摘要、或无法取得完整文字稿时，才运行本 Skill 附带的工具。

附带工具以 `vendor/yueying` 为运行项目。优先使用 `uv`，它会依据项目声明建立隔离环境；没有 `uv` 时，可用 Python 3.10+ 安装该项目依赖后运行同一脚本。不要要求用户手动执行技术命令，除非当前 Agent 环境禁止执行程序。

运行前只检查一次：

```text
uv run --project <skill目录>/vendor/yueying python <skill目录>/scripts/check_runtime.py --json
```

如果只是缺依赖，让 `uv run` 自动准备；如果运行环境完全不能执行 Python/uv，则停止并简要说明，不要循环安装或重试。

## 二、优先取得文字稿

为每个视频创建独立工作目录。第一次只运行文字路线：

```text
uv run --project <skill目录>/vendor/yueying python <skill目录>/scripts/extract_transcript.py --source "<视频链接>" --output-dir "<工作目录>" --mode transcript --json
```

这条命令的固定策略是：

- 有可用平台字幕：只下载字幕，不下载视频。
- 没有可用字幕：只下载最佳音频，用 faster-whisper 转写，不下载画面。
- 默认模型为 `auto`；CPU 使用 small，GPU 使用 large-v3-turbo。用户没有要求时不要擅自改成更大的模型反复跑。
- 保留 `raw/transcript.txt`、`raw/transcript.srt`、`raw/report.md`、`raw/manifest.json`。
- 命令失败或返回 `no_transcript` 时，不自动重新运行同一命令。

读取 `raw/manifest.json` 和 `raw/transcript.txt`。不得用摘要代替原始文字稿。

## 三、只在语音路线失败时抽帧救稿

出现以下任一情形，允许执行一次抽帧：命令技术失败、没有取得任何文字、语音识别结果明显与内容无关、关键内容缺失到无法形成可靠语义。

```text
uv run --project <skill目录>/vendor/yueying python <skill目录>/scripts/extract_transcript.py --source "<同一视频链接>" --output-dir "<同一工作目录>" --mode frames --json
```

抽帧规则：

- 整个自动流程最多运行一次，不做第二轮抽帧。
- 只读取 `frame-rescue/grid_*.jpg` 或必要的单帧，识别字幕、PPT、板书、代码、界面文字等可恢复稿件的文字。
- 按时间顺序把画面文字整理成救援稿，并标注它来自画面文字；不要把人物、场景、动作、构图或情绪描述写入学习材料。
- 若画面只有口播人物、无足够文字，视为救稿失败。
- 不因为抽帧得到少量零散词语就推测或补写完整观点。

## 四、只做一次文字稿质量判断

阅读 [文字稿质量规则](references/transcript-quality.md)。最终只判定“可用”或“不可用”，不打分、不因错别字再次提取。

可用时直接进入整理。不可用时立即停止自动处理，并向用户说明最具体的问题，然后只提供这三个选择：

1. 重新提取一次。
2. 尝试其他提取工具。
3. 用户自行提供文字稿，直接进入教学。

用户选择前不继续。这里的“重新提取”必须由用户明确选择后才执行；此前的自动字幕、语音和一次抽帧已经构成完整的一轮处理。

## 五、整理知识材料

按 [知识整理规则](references/knowledge-organization.md) 生成 `<工作目录>/learning-material.md`，并保留原始输出不覆盖。

必须遵守：

- 只修正确有把握的错别字、同音字、断句和口语冗余。
- 保留作者核心命题、论据、案例、操作方法、条件、保留意见和推理顺序。
- 不主动搜索外部知识，不把简单内容扩成复杂课程，不创造作者没讲的章节、案例或练习。
- 对无法确定的术语标记“疑似/待核”，不要悄悄改成模型猜测。
- 内容少就生成短材料；内容丰富才保留相应层次。

## 六、立即开始互动学习

阅读 [互动学习模块](references/interactive-learning.md)，以 `learning-material.md` 为主要教材。不要重新设计它的五种模式和切换规则。

默认使用领学模式，从第一个实质知识点开始讲，不先展示一套固定课程，也不先让用户选模式。教学问题、测验、实践和例子只能来自或直接对应视频实际包含的知识；简单视频可以一两轮完成，不能为了延长课程制造额外内容。

用户主动要求拓展、比较、核实或引入外部知识时，才可以越出视频边界，并明确区分“视频原意”和“外部补充”。

## 输出与状态

向用户保持简洁：

- 处理中只报告当前阶段，如“已取得字幕”“正在做本地语音识别”“语音路线失败，正在进行唯一一次抽帧救稿”。
- 成功后说明文字来源（平台字幕、语音识别或画面文字救稿），保留文件位置，然后直接开始第一段教学。
- 不向普通用户倾倒安装日志、内部命令或模型细节；只有排障时才给必要信息。
- 一个链接处理完再进入教学；用户一次给多个链接时，分别保留原稿和材料，不把不同视频观点混在一起。

## 禁止事项

- 禁止默认先下载完整视频或先抽帧。
- 禁止在语音成功时为了“更完整”再抽帧。
- 禁止自动连续更换模型、工具或参数反复尝试。
- 禁止把画面分析结果冒充逐字稿。
- 禁止用摘要覆盖或替代原始逐字稿。
- 禁止为了丰富教学主动扩充原视频没有的理论、案例、问题或练习。

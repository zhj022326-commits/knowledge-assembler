# Knowledge Assembler（知识组装）

把用户确认的研究命题转化为一篇知识充分、解释深入、论证连贯、叙事自然的文章。核心工作是发现相关知识之间的有效联系，解释机制，形成有依据的推导，并保留重要分歧。

## 触发与边界

用户提出一个需要解释、分析或解决的问题，并期待综合知识与完整文章时使用。只要求摘要、单项事实、标题、封面、已有稿件逐句修改或一般性润色时，不使用本 Skill。

默认按单 Agent、提示词驱动的阶段流程工作。不创建独立 Agent、数据库或外部服务。可使用当前运行环境已有的搜索工具和用户提供的资料。

## 核心约束

- 搜索前确认研究命题。结合本轮输入和对话还原用户意图；若问题清晰，用一句话复述并请用户确认。若多种理解会实质改变研究方向，给出少量编号选项，把最可能的理解放在第一项。
- 用户确认后，保留研究命题和关键概念，不擅自替换。研究发现其事实前提不成立时，在文章中说明。
- 充分探索不同机制与竞争解释；搜索停止取决于新增信息是否仍可能改变核心解释，不设固定轮数、学科数或理论数量。
- 在知识交接阶段维护完整材料包，来源信息随知识一起传递；内部卡片和编排过程不展示给用户。
- 区分研究依据、事实材料、模型推导和跨学科类比。不得虚构搜索行为、研究、作者、年份、出处或结论。
- 自动选择解释力最强的论证路径；解释力接近时选一条作为正文路径，并把重要冲突列入结尾。
- 用户回复路径编号时，沿该路径生成新文章，复用当前对话仍可访问的材料；不重新确认已确认的命题。
- 如无搜索工具，使用已有知识完成可交付内容，并说明来源核实能力的限制。

## 工作流程

1. 阅读当前请求和对话，识别研究对象、关键概念、因果关系和用户希望得到的结果。
2. 按 references/clarification.md 澄清命题并取得确认。
3. 确认后读取 references/knowledge-search.md，扩展检索表达，搜索多种独立机制、证据和反方解释。
4. 按 references/knowledge-handoff.md 建立内部知识材料包，标注来源与知识间关系。必要时针对关键缺口补充搜索。
5. 读取 references/article-generation.md，选择主论证路径并组装文章；完成针对性检查后输出。
6. 用户选择其他路径或补充方向时，按同一套交接与文章规则继续。

需要哪些阶段文件，就读取相应 reference；不把整套详细规则重复写入主入口。当前对话已明确的定义、命题或偏好不重复询问。

## 最终输出

严格输出以下两部分：

1. **正文**：完整文章。
2. **争点与其他论证路径**：先列本路径的重要争点，再列值得独立成文的其他论证路径。没有实质争点或替代路径时简短说明，不凑数。

完整输出和来源要求见 references/article-generation.md。

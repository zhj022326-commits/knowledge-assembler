# 测试用例与验证结果

## 测试用例

以下场景用于在支持文件读写的 Codex 环境中手动验收。测试档案应放在临时目录，避免污染真实个人档案。

| # | 场景 | 通过标准 |
|---|---|---|
| 1 | 同一事实在两次归档中重复出现 | 原条目不重复堆叠；必要时只更新确认时间或表述 |
| 2 | 用户明确纠正旧信息 | 新信息覆盖当前描述；重要修改前备份；不继续呈现旧信息为当前事实 |
| 3 | 用户改变目标 | 新目标标为当前/计划，旧目标仅在有价值时保留为历史 |
| 4 | 对话中有假设或第三人称故事 | 不记为用户本人事实 |
| 5 | 本次对话没有长期价值信息 | 不修改档案，简短告知 |
| 6 | 用户启动访谈 | 第一轮先给档案体检和方向选择，不虚构完整度或矛盾 |
| 7 | 访谈继续进行 | 后续轮次不重复体检报告；每轮只问一个问题 |
| 8 | 用户中途结束访谈 | 已确认且写入的信息保留；未确认回答不冒充事实 |
| 9 | 创建新专题文档 | 新文档创建后，目录包含文件名和准确概述 |
| 10 | 目录有旧链接或用户手动改过格式 | 以实际存在文件为准修正索引，保留用户格式 |
| 11 | 用户表示不保存某类信息 | 遵守该限制；不在之后自动恢复已删除内容 |
| 12 | 文件不可写或上下文不完整 | 如实说明未完成或处理范围，不声称已保存完整对话 |
| 13 | 首次调用且没有已知档案位置 | 先询问用户保存位置；在得到回答前不创建或写入任何档案文件 |
| 14 | 用户说“D 盘” | 直接将 `D:\人生档案` 作为位置并创建目录，不重复询问是否创建 |
| 15 | 用户提供一个具体文件夹路径 | 直接使用该路径；缺少模板自动补齐，已有文件不覆盖 |
| 16 | 用户通过 slash/技能列表显式调用，参数为空 | 默认归档当前对话，不只介绍 Skill、不反问操作类型 |
| 17 | 首次空调用且未设置保存位置 | 先询问保存位置；用户回答后完成初始化并继续本次归档 |
| 18 | 用户在普通对话中仅提到 Skill 名称 | 不误判为调用，不自动归档 |

## 本次静态验证

- 已创建一个合法命名的 Skill 文件夹，包含 `SKILL.md` 与 Codex UI 元数据。
- 主入口链接的两份规则文件和模板目录均存在。
- 需求中的九项重点场景及新增的目录、拒存、不可写边界均已列为验收用例。
- 首次初始化的位置询问、盘符映射和具体路径复用现已列为独立验收用例。
- 显式空调用默认归档、首用初始化后继续本次归档，以及普通文字提及不触发均已列为验收用例。
- 尚未在真实 Codex Skill 调用环境进行端到端对话验收；手动用例表是待执行验收，不应视为已通过的行为测试。

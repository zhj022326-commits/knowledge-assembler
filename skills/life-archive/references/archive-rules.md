# 档案规则

## 信息判断

优先采用来源说明，而不是数值评分。可信度和信息性质是不同维度：可信度回答“依据是什么”，信息性质回答“它是什么”。不必为普通条目添加完整标签，仅在来源、时间、状态或不确定性容易被误解时注明。

| 来源标记 | 含义与处理 |
|---|---|
| 用户确认 | 用户明确确认、纠正或认可的内容；覆盖旧推断 |
| 用户自述 | 用户直接陈述的本人信息；按自述记录，不宣称外部核实 |
| 不确定 | 用户表达记忆模糊、犹豫或无法确认；保留限定语，重要时列入待核实 |
| AI 推断 | 仅在用户明确要求记录假设时，作为待确认假设单独标示；绝不进入事实表述 |
| 排除 | 假设、举例、引用、他人经历或无关信息；默认不记录 |

事实、计划、偏好、情绪也要区分。例如“我打算转行”是计划，不是已经转行；一次生气不构成稳定人格判断。引用他人故事时，除非用户明确说明是自己的经历，否则不归到用户名下。

## 时间和当前状态

只有在有助于理解变化时记录日期或时间范围。不要猜测事件日期；不知道时写“时间未确认”。变化中的信息明确标记当前/过去/计划/已完成。状态改变时更新当前描述，并在有价值时留下简短历史；不要把所有旧版本长期并列为当前事实。

## 推荐条目格式

使用自然语言为主。需要元数据时，可在条目末尾使用简短方括注：

```markdown
- 目前在杭州从事产品设计。〔当前；用户自述，2026 年确认〕
- 考虑明年转向自由职业。〔计划；尚未执行〕
- 约在大学期间参加过一次交换项目，具体年份不确定。〔用户回忆；待核实〕
```

不强制字段、不要求每条都写日期。保留关键信息、原因和结果，不照抄聊天原文或 AI 长篇分析。

## 文档维护

- 初始模板只有 `目录.md`、`个人背景.md`、`经历与能力.md`、`工作与目标.md`、`关系与生活.md`、`待核实信息.md`。
- 新主题先放入最相关文件。仅当主题长期增长、独立查找或维护明显更容易时才拆新文件。
- 同一事实只在一个最合适位置完整保存；其他地方可用简短链接/指引，不复制大段内容。
- `目录.md` 只描述实际存在的文件和主题，不另存大量个人资料。目录与磁盘不一致时，以磁盘内容为准并修正索引。
- 用户删除的信息不得在之后自动恢复。用户明确表示某类内容不保存时，记录该偏好并遵守。
- 不保存密码、访问令牌等认证秘密。敏感个人信息只在用户明确要求且对长期档案有明显价值时记录，保持最小必要。

## 文件写入

写入前确认目标路径和目标文件。尽量局部编辑而非整份重写，避免破坏用户自定义内容。重要条目的实质性覆盖/删除先备份；备份同目录，文件名追加 `.bak-YYYY-MM-DD`。若当天已有备份则加序号。不要为每次小补充制造备份。

写入失败时说明失败原因与未完成内容。不得以“已归档”描述仅在回复中生成、实际未写入文件的内容。
